# Gather · 社区活动报名

这是一个能在本地运行的小项目，使用 React、TypeScript 和 FastAPI。页面、后端和演示数据都已准备好，你需要在它的基础上完成下面的需求。

这是一次20分钟的开发练习，安装环境不计时，可以使用AI工具和搜索。活动、人员和邮箱都是虚构的，成果只用于面试评估，不用于商业交付，也不需要面试后继续补做。

## 我们想做什么

我们用这个工作台管理社区活动。现在可以看活动、查名额和名单，也能添加报名。不过活动满了、有人退出或者名额临时变化时，还需要工作人员自己处理。希望你把这段流程补起来。

具体来说：

1. **满员后也能登记。** 有名额时正常报名，满员后进入候补，让工作人员知道谁在等。同一个人在同一场活动里，不应该重复占名额或重复候补。
2. **有人退出后，空位能自动补上。** 退出记录要保留，按报名先后安排仍在等待的人。已经退出的人不应该继续占位，也不应该被自动安排回来。
3. **活动名额可以调整。** 增加名额后，把空位安排给候补的人。减少名额时，要考虑已经确认的报名，不能没说清楚就改变这些人的安排。
4. **页面上的信息要对得上。** 能看清谁已报名、谁在候补、谁已退出，活动卡片和名单里的人数要一致。多人同时操作或重复点击，也不能超额报名、重复占位或弄乱补位顺序。不同活动之间互不影响。
5. **操作失败后能继续处理。** 页面要告诉工作人员发生了什么，恢复后可以重试。有时候数据已经保存了，但页面没收到成功响应；这种情况下再点一次，也不能多出一条报名或让人重新排队。页面底部有故障模拟工具，可以用来验证。

## 启动

需要 Node.js 20+、pnpm 9+ 和 uv。Python 3.11+ 可由 uv 自动准备。请在面试计时前完成安装并确认页面可打开。

```sh
git clone https://github.com/emagen-ai/gather-workshop.git
cd gather-workshop
pnpm install --frozen-lockfile
pnpm run setup:api
pnpm dev
```

打开 **http://127.0.0.1:5177**。前端使用 5177，后端使用 8765；请确保两个端口没有被占用。按 Ctrl+C 停止。若缺 pnpm，可先执行 `npm install -g pnpm@9.15.9`；uv 安装方法见 <https://docs.astral.sh/uv/getting-started/installation/>。

`pnpm dev` 会同时启动网页和 API，前后端保存代码后都会自动重载。当前示例刻意使用单进程内存存储，不需要数据库、Docker、账号、密钥或外部 AI 服务。后端重载或重启会恢复初始数据；单纯刷新网页不会清空数据。

## 现有功能

- 切换三个活动，查看名额与报名名单。
- 添加报名，校验输入、重复报名和满员。
- 刷新列表；刷新浏览器后能重新读取同一个运行中的 API 数据。
- 页面底部“演示工具”可以模拟写入失败和恢复初始数据。

“故障模式”有两种：写入前失败携带 `X-Demo-Fail: 1`，API 在修改数据前返回 503；写入后响应丢失携带 `X-Demo-Fail: after`，API 执行成功后将成功响应替换为 503。两种模式的读取都正常。恢复数据本身也是写请求，需要先切回“正常请求”。
